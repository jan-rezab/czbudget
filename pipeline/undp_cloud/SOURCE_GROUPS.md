# Bounded original-source batches

The checked manifest partitions all 108 audit descriptors exactly once into education (20), annex (22), inequality (9), AI (11), care (20), BRFSS (4), PISA (1), and remaining documents/claims (21). The loader rejects a missing, extra or duplicate source assignment. The default `--source-group all` preserves the legacy bundle; named groups publish to `hdr_report_sources_2025:<group>`.

Cloud Build substitutions are `_SOURCE_GROUP`, `_RESUME_RUN` (empty by default), `_WID_SHARD_INDEX` (0) and `_WID_SHARD_COUNT` (1). `_LOADER_SHA` remains required. An empty resume value means no resume; nonempty values must be exact UUIDs. All execution remains the data plane in europe-west4. This change does not submit jobs or alter website code.

WID country/region expansion happens only after selecting its inequality descriptor. Codes are sorted from the original official catalogue, then partitioned by index modulo shard count. Counts must be 1–32, with index below count. Sharding requires the inequality group. Non-WID inequality descriptors are processed only in shard 0. Each shard publishes to `hdr_report_sources_2025:inequality-wid-i-of-N` and records the full catalogue count and selected source codes. Regional source codes remain visible; this is not a claim every code is a country. Source filtering retains received, accepted and excluded row counts and original age/population/quality fields. Each provider download retains the 2GB and 10-minute bounds; unavailable sources remain explicit.

Current-source views accept legacy and named-group pointers. The newest pointer wins per source ID using the source catalogue, preventing duplicate rows from legacy/group overlap while keeping untouched sources on the legacy release. Publication replaces staged release IDs with the current run ID, allowing validated stages from older runs. Atomic publication retries at most three times, with 1/2-second backoff, only when the transaction is confirmed aborted due to a concurrent update and the matching ingestion receipt is absent. A matching committed receipt prevents replay; unknown failures without a confirmed receipt are not retried.

Each complete source writes a processed checkpoint containing the exact raw source hash and generation, immutable gzip stage URI/generation/hash, record count and parser Git SHA. Resume checks raw identity and hash, then the pinned stage generation and checksums, every stage row's source identity and total count. Source stages are written only after complete parsing. Failed or partial sources never enter the stage list.

`education_resume.json` records the two completed UIS stages from canceled run `5dc392de-1b7f-48d2-913f-99ca35774c51`: SDG 3,765,338 records and OPRI 9,951,585 records. Counts were read from original Cloud Build completion log entries; GCS generation, MD5 and raw receipts were inspected without local bulk downloads. The prior parser SHA is `bc5d30c0d0b349d7b10181ba1ec76b2852e081f4`. Those legacy stages lack processed checkpoints, so the cloud worker computes the stage SHA256 and independently verifies every row/count before reuse. Only an exact matching resume UUID admits this exception.

Cloud schema previews live under each run's `schema-previews/`: CSV headers, statistical labels/types, workbook sheets/types and the first ten cached source aggregate workbook rows. Individual respondent values from CSV/statistical microdata are never included. These previews support reviewed bindings; they are not public observations or a claim semantic normalization has occurred.

Six source-fidelity and ten batch/recovery synthetic tests pass. No live batch or publication was submitted during implementation.
