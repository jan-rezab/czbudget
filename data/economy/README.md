# Global economic data layer

This directory is generated by `python3 scripts/build-country-economy.py` from
the versioned contract in `data/contracts/economic-series.v1.json`.

## Files

- `economic-observations.v1.csv.gz` — long fact table; one untouched source
  observation per country, source series and period.
- `economic-indicators.v1.json` — country dimension, report-facing indicator
  definitions and source registry.
- `economic-coverage.v1.json` — first/last period, observation count and source
  series count by country, indicator and frequency.
- `economy-deep-dive.v1.json` — compact browser mart for the 17 benchmark
  countries. It is intentionally not the global analytical fact table.
- `manifest.v1.json` — counts, SHA-256 hashes and raw-snapshot lineage.

Raw dated downloads are retained in `../data/sources/economy/YYYY-MM-DD/` and
are not served by the website.

## Fact grain and key

The candidate natural key is:

`country_code + source_id + source_key + frequency + period + retrieved_at`

`indicator_code` is a curated reporting label. `source_key` and
`source_series` preserve the complete source-dimensional identity. Reports must
filter the unit, transformation and seasonal adjustment explicitly; they must
not average multiple variants of the same concept.

Important fields:

| Field | Meaning |
| --- | --- |
| `country_code` | ISO-3/economy code; regional aggregates are excluded |
| `indicator_code` | Stable portal-facing concept |
| `source_series` | Human-readable source dimension key |
| `source_key` | Full key used to keep variants separate |
| `frequency` | `A`, `Q` or `M` |
| `period` | Original annual, quarterly or monthly period |
| `observation_date` | Comparable period-end/period-anchor date |
| `value`, `unit` | Source value and source unit; no conversion or imputation |
| `seasonal_adjustment` | Source adjustment code |
| `transformation` | Source level/growth transformation code |
| `source_vintage` | Dataset edition or last-updated marker |
| `retrieved_at` | Reproducible download timestamp |

## Recommended analytical windows

- Descriptive annual reporting: 1995 onward (roughly 30 years).
- Business-cycle work: 2000 onward, preferably at least 80 quarters or 120
  monthly observations.
- Structural relationships: use 40–60 annual observations where definitions
  remain comparable, then test shorter regimes separately.
- Twenty annual observations are acceptable for transparent trend reporting,
  but too thin for a large multivariate model or confident causal claims.

Longer history does not solve breaks, non-stationarity, reverse causality or
omitted variables. Any policy-impact report needs a separate identification
strategy and should record its sample selection alongside the result.

## Warehouse use

`pipeline/warehouse/schema.sql` defines:

- `economic_countries`
- `economic_indicators`
- `economic_observations`
- `economic_series_coverage`
- `latest_economic_observations`

The observation table is partitioned by `observation_date` and clustered by
country, indicator, source and frequency. Queries should always bound the date
range first and select only required columns.
